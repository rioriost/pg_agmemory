## Decision and scope

Add `pg-agmemory mcp` as a **local stdio adapter to the authenticated Native
HTTP API**. Keep PostgreSQL as the only application persistence store and Native
models/service/RLS as the memory and authorization contract. The adapter is
a trusted Native client, not a new database client, policy engine, or remote
multi-user MCP service. It maintains no semantic/response cache or durable retry
store. The application version becomes v0.0.8; **schema remains 7 with no new
migration, DDL, or backfill from v0.0.7**.

An optional `pg-agmemory[mcp]` extra pins official **mcp 2.2.0** and
**httpx 0.28.1**. Both test and runtime Docker stages include it; base package
users need not install the MCP extra. Local validation uses **Apple Container**,
not Docker Desktop, and CI uses Docker on native **linux/amd64** and
**linux/arm64**. Historical final results for this milestone are recorded below.

No remote MCP HTTP/Streamable HTTP/SSE listener, OAuth, caller identity
delegation, arbitrary headers/URLs, agent harness execution, or generalized
SDK is added. The adapter's outbound Native HTTP is not a remote MCP transport.

## Four tools, one Native contract

Input/output JSON Schemas are generated from the Native Pydantic models rather
than handwritten copies:

| Tool | Arguments | Native operation |
|---|---|---|
| `memory_recall` | `{request: <Recall>}` | `POST /v1/recall` |
| `memory_remember` | `{request: <Remember>, idempotency_key: "..."}` | `POST /v1/remember` |
| `memory_explain` | `{request: <Explain>}` | `POST /v1/explain` |
| `memory_forget` | `{request: <Forget>, idempotency_key: "..."}` | `POST /v1/forget` |

The body is unchanged Native input. Remember is only explicitly requested
structured memory with `explicit_intent: true` and literal same-scope episode
evidence; no free-form extraction, automatic capture, or synthesis is implied.
Capture episodes via Native `observe`, not MCP. Jobs, revisions, graph,
checkpoint/effect operations, and deletion-receipt lookup are not MCP tools.

Recall preserves coverage, current ACL/deletion checks, time selection, and
evidence freshness warnings. `simple-v1` remains default; Japanese
`ja-janome-0.5.0-v1` remains opt-in. `token_budget` and
`tokenizer_id: "utf8-bytes-v1"` still budget **UTF-8 bytes, not model tokens**.
Explain's omitted revision means **1, not latest**. Returned memory is
untrusted evidence, not instructions or verified current external truth.
Forget retains explicit-ID preview/purge and operator-managed backup status.
Native preview and purge **both return HTTP 202**, unchanged; the response
variant distinguishes a non-mutating preview from an active-store purge receipt.

## Idempotency and uncertain outcomes

Both mutation tools require a caller-supplied `idempotency_key`, including
forget preview: **1–256 visible ASCII characters (`0x21`–`0x7e`, no whitespace)**.
Whitespace is rejected, not trimmed; exactly 256 characters is allowed and 257
is rejected. The unchanged key becomes Native `Idempotency-Key`.
Do not generate keys from MCP request or
session IDs: those are neither durable memory run IDs nor HTTP idempotency keys.

The caller must retain the key/body before dispatch and reuse the **same key
and body after uncertainty, even across stdio restart or token refresh**.
There are no automatic retries or autogenerated keys. A new key after a lost
acknowledgement can duplicate an operation. A changed body with the same key can
conflict. Native replay returns historical references under **current**
authorization and deletion checks; it is not a fresh read and cannot resurrect
purged content. Restoring a session does not restore revoked access.

Success returns `structuredContent: {result: <validated Native result>, error: null}`.
Failures return `isError: true` with
`structuredContent: {result: null, error: {code, retryable, outcome_unknown,
native_status, request_id}}`. Native status and validated Native request UUID
may be null. The request UUID is not the MCP request ID. Short text does not
duplicate evidence or echo raw requests, responses, URLs, or credentials.

Transport errors/timeouts, 5xx, and invalid/unexpected mutation responses are
conservatively `outcome_unknown: true`: **do not claim rollback**. A Native
commit may precede an interrupted HTTP or stdio acknowledgement.
`retryable` is a hint, not proof of non-commit or permission to change key/body.
Local input validation can fail before HTTP submission; uncertain dispatched
operations require caller-controlled same-key recovery.

## Fixed startup identity and bounded HTTP

Trusted startup configuration supplies only the adapter's fixed
`PGAG_MCP_API_URL` and `PGAG_MCP_API_TOKEN`. The URL must be an HTTPS origin or
loopback HTTP origin, with no credentials, application path, query, or fragment;
a root `/` is accepted. TLS verification remains enabled, redirects are
disabled, and HTTP client configuration ignores proxy environment settings.

The bearer token is for the **Native API audience**, which the Native API checks
alongside issuer/signature/expiry and subject mapping. It is not forwarding an
MCP caller token or delegated identity. No per-call URL, headers, token, or
identity override exists. `--subject` and `--once` are rejected for `mcp`.
The adapter needs no database credentials or JWT signing key.

Authenticated startup `GET /v1/capabilities` must match `api_version: "v1"`,
`service_version: "0.0.8"`, and `schema_version: 7` before stdio is served.
Failures exit nonzero with sanitized diagnostics, never secrets.
Restart to refresh the fixed token; there is no automatic refresh.
Native authentication, current ACLs, and deletion are checked on every call,
not cached by the startup probe.

HTTP limits are **20 seconds total**, **10 seconds I/O**, **5 seconds connect**,
**4 connections**, **256 KiB serialized Native request**, and **2 MiB HTTP
response**. These are transport bounds, not host/stdio buffer guarantees,
model-token budgeting, performance qualification, or deployment sizing.

## Trust and deletion boundary

Run **one adapter per trusted identity**, without cross-trust sharing or
network exposure. The local host can exercise that identity's Native permissions.
No remote MCP authentication, OAuth, or delegation makes such exposure safe.

The Native API's response-drain barrier covers HTTP delivery **to the adapter**.
It does **not** extend atomically through stdio, host UI, or LLM context
consumption. A pre-purge/pre-revocation response can remain in adapter/pipe/host
buffers or already-delivered context even without a response cache.
Those bytes cannot be retracted. After forget or ACL changes, the host must
discard cached context and obtain fresh authorized data; there is **no MCP
deletion notification** to enforce that host action.

This additional trusted-client boundary does not weaken Native active-store
purge or current-authorization replay, but it must not be described as an
end-to-end host deletion barrier. WAL, replicas, backups, retained metadata, and
previously delivered context remain outside full-erasure qualification.

## Dependency and protocol evidence

The [official SDK v2.2.0 release](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.2.0)
was published **2026-09-07** (not a prerelease), verified from official release
metadata on 2026-09-17. Its
[protocol documentation](https://py.sdk.modelcontextprotocol.io/protocol-versions/)
describes modern **`2026-07-28` `server/discover`** and the legacy
**`2025-11-25` `initialize`** era.

These upstream facts do not prove adapter compatibility. Separately, targeted
checks have exercised actual stdio SDK `Client` modes and raw JSON fixtures:

| Exercised mode | Protocol exchange |
|---|---|
| Modern `2026-07-28`, SDK `Client(mode="auto")` | `server/discover`; raw requests include per-request `params._meta` keys `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientInfo`, and `io.modelcontextprotocol/clientCapabilities` |
| Legacy `2025-11-25`, SDK `Client(mode="legacy")` | `initialize` with `protocolVersion`, `clientInfo`, and `capabilities`, followed by `notifications/initialized` before tool calls |

The runtime smoke launches the actual `pg-agmemory mcp` child in the non-root
production image against its loopback Native API, with a fixed token and
provisioned scope. It verifies the four-tool list and recall in **both modes**;
existing Japanese/API/worker smokes remain. The current CI step is
`Test containers and smoke-test production API, worker, and MCP`.
The runner requires `jq` for both Apple Container and Docker.

Final Apple Container/native Docker results are recorded below.
Do not claim unverified older clients, all
historical protocol versions, or named host compatibility from these checks.
